# Setward (formerly Chalk): notes for working on this repo

Free, offline-first workout logger. React 19 + TypeScript + Vite 8 PWA, Dexie (IndexedDB), no backend. The owner wants development and hosting to stay free, so don't add paid services or dependencies that need them.

**Project memory** is in `.ai/`: start with `PROJECT_STATE.md` and `CURRENT_TASK.md`. The roadmap, requirements, protected invariants (`NON_NEGOTIABLES.md`), test evidence and smoke tests live there too. Update it as you work.

**Branding and continuity:** the visible app is now **Setward**. Its split-S geometry is in `src/lib/brand.ts`, rendered by `src/components/Brand.tsx` and `src/lib/shareCard.ts`; install icons are in `public/`, and reusable artwork/usage notes are in `branding/`. Keep the legacy `chalk` database name, backup `app: 'chalk'`, `chalk-sync/1` format, existing sync repository and `/chalk/` hosting/PWA scope unchanged for compatibility. Remaining internal `chalk` names are intentional; do not globally replace them.

**Handoff:** check the working tree as well as `.ai/` before making changes. Completed work may be saved locally but uncommitted. Preserve it, read the recorded validation and outstanding steps, and do not treat a completed local change as deployed. ## Commands
- `npm run dev`: dev server on :5173 (also `.claude/launch.json` → `chalk-dev`)
- `npm run build`: `tsc --noEmit` + production build with service worker. In Git Bash, a sub-path build needs `MSYS_NO_PATHCONV=1 BASE_PATH=/chalk/ npm run build`; otherwise MSYS rewrites the path and the page loads blank.
- `npm test`: vitest. It covers the sync engine, records and weekly stats, CSV import and export, parsing, backups, the live workout and the plate solver. Dexie code runs on `fake-indexeddb` (dev only). The live GitHub check is opt-in: `CHALK_SMOKE_REPO=owner/name CHALK_SMOKE_TOKEN=… npx vitest run github.smoke`. It writes to `data/` in that repo and then deletes it.
- `node scripts/sample-backup.mjs`: writes `tmp-import/chalk-sample-backup.json`, about four months of the owner's style of training, for QA. Restore it in a dev browser only.
- `npm run exercises`: re-downloads free-exercise-db and rewrites `src/data/exercises.json`. Bump `LIBRARY_VERSION` in `src/db.ts` afterwards so installed apps re-seed.

## Architecture
- **Storage units:** weight in kg, distance in km, duration in seconds. Converting to lbs/mi only happens at display and input time (`src/lib/format.ts`).
- **Workouts** are documents with nested exercises and sets. `exerciseIds` is denormalised for a multi-entry index.
- **The in-progress workout** lives in the `kv` table under `active`. The editor writes through `updateActive()` on every change, so a closed tab loses nothing. Text inputs bound to the DB must use `BufferedText`/`NumberField` (`src/components/fields.tsx`); otherwise the async round trip makes the caret jump.
- **`WorkoutEditor`** has three modes: `live` (checkboxes + rest timer), `edit` (past workout) and `routine` (template).
- **`DataProvider`** (`src/lib/data.tsx`) loads every exercise and workout and computes personal records once. Pages read them through `useData()`.
- **Routing** is a tiny hash router (`src/lib/router.tsx`) so the app works from any static path, like GitHub Pages `/<repo>/`.
- **Cloud sync** writes to a private GitHub repo of the user's choosing through a fine-grained PAT (the owner uses `botrading20-glitch/chalk-data`).
  - `syncCore.ts` is a pure three-way merge against a per-device base snapshot (hashes of records at the last sync), so deletions need no tombstones.
  - Workouts are split into 16 shard files by id hash; routines, custom exercises and settings each get one file under `data/`.
  - `github.ts` uses the Contents API with sha-based optimistic concurrency (409/422 → `SyncConflict` → retry).
  - `sync.ts` is the IndexedDB adapter plus triggers: Dexie `storagemutated`, `visibilitychange`, `online`, and `updateSettings`.
  - Synced records must stay plain JSON. The active workout and the exercise library are not synced.
- **Library exercises** are re-seeded with `bulkPut` whenever `LIBRARY_VERSION` changes, so they're never edited in place. Editing one saves a custom copy with `replaces: <library id>` and moves history onto it (`reassignExercise` in `src/lib/exercises.ts`). `useData().exercises` hides replaced originals, but `exerciseMap` keeps them so old references still resolve.
- **Body weight** has its own `bodyweight` table: one weigh-in per day, in kg, with `date` at local midnight. It syncs and backs up like workouts.
- **Rest alert with the screen off** (`src/lib/restAlert.ts`, setting `timerLockScreen`, on by default). While resting, Chalk plays a generated near-silent WAV. It keeps the app alive on a locked phone and shows the rest as a lock-screen player (Media Session: ±15 s, and pause ends the rest). The beep is the Web Audio one from `timer.ts`, fired by a timer, because Web Audio doesn't take audio focus. Tested on Android: an audible `<audio>` beep paused Spotify for good. With the current design, Spotify keeps playing and the beep is on time while locked. The track only beeps itself `FALLBACK` seconds late, as a backup when the app was frozen and the in-app beep couldn't play.
- **Routine folders** are only a `folder` name on each routine (`src/lib/folders.ts`), so they sync with routines and vanish when empty. Which folders are collapsed is per device, kept in `kv` under `collapsedFolders`. `saveRoutine` merges over the stored routine so editors that don't know about `folder` keep it.
- **Plate calculator** (exercise ⋯ menu in the workout editor): `src/lib/plates.ts` finds the fewest plates per side with a small DP, not greedy, so a gym without some plate sizes still gets exact loads. It works in the user's unit (kg or lb plates). Plate sizes owned and the bar per exercise (`plateBars`, in kg, snapped to 20 kg ↔ 45 lb) live in settings.
- **Warm-ups** (`src/lib/warmup.ts`, pure): the working weight and the steps in settings (`warmupSteps`, `warmupEmptyBar`, `warmupRoundKg` / `warmupRoundLbs`) become sets whose loads `calculatePlates` can make (nearest, a tie goes lower, never under the bar); other equipment rounds to the step. `addWarmups` in `WorkoutEditor` inserts them from the exercise ⋯ menu (replacing old ones only after a confirmation); the steps are edited on `#/settings/warmup` (`WarmupSection.tsx`).
- **Live record alerts:** `liveRecordSets` / `newLiveRecords` (`src/lib/records.ts`) follow the same rules as `computeRecords` (NN-09), so the trophies add up to the saved total; off while editing a saved workout. The plate button, stopwatch toggle and superset scroll are settings read in `WorkoutEditor`.
- **Muscle map:** `muscleSets` (`src/lib/muscles.ts`) counts a set once for the main muscle and half for each helper, warm-ups out; `MuscleMap` draws an original SVG figure (left half mirrored) with a table as the text alternative. It shows in the live workout's sheet, on the workout page, in the monthly report and on Progress.
- **Monthly report:** `src/lib/report.ts` (pure; months are local time) and the lazy page `src/pages/Report.tsx` at `#/profile/report/<yyyy-mm>` (a missing or out-of-range month falls back to the current one). Home's `ReportCard` shows last month's report once in a month's first week, remembered by the pref `reportSeenMonth`; the setting is `monthlyReport`. The weekly chart in `Profile.tsx` has a Reps metric and a 3, 6 or 12 month range.
- **Help guides** (`src/pages/settings/HelpSections.tsx`): five-step guides whose pictures are the app's own classes drawn static (`aria-hidden`, `inert`), so they follow every theme and language; the Questions page reuses the `about.q1` to `about.a5` keys.
- **Set videos** (NN-19): `src/lib/media.ts` and the Dexie `media` table (`db.version(3)`), one blob per set found by `setId` and `workoutId`. `SetVideo.tsx` has the set menu's Video section (`VideoSection`, the camera app through `<input capture>`) and the player (`VideoSheet`, object URL, speed chips, share). A video follows its workout: `finishActive`, `discardActive`, the workout page's delete, the past-workout editor's save and discard, and `wipeAllData` clean up through `removeVideosForWorkout`; removing a set or exercise that has one asks first. `orphanVideos` finds videos whose set is in no saved workout, no workout in progress and no editor draft; the Data page card (`VideosCard`) clears those or all. They are never synced or in a backup. The in-app browser cannot pick a file: make a clip with `canvas.captureStream` and `MediaRecorder` and call `attachVideo` from the page console.
- **CSV text cells** are neutralised against spreadsheet formulas (`escapeCell` / `unescapeCell` in `csv.ts`); the pound is exactly `KG_PER_LB` = 0.45359237 (`format.ts`).
- **Settings screens** (`src/pages/settings/`): `#/settings` is a grouped list, `#/settings/<id>` one page per row (`Section.tsx` maps ids to pages); the whole tree is a lazy chunk. A new setting needs its field in `Settings` (`types.ts`), `DEFAULT_SETTINGS` (`db.ts`), `cleanSettings` (`validate.ts`), strings in `src/i18n/en/settingsPages.ts`, a control on its page and a summary on `Home.tsx` if it changes the row's text. Plain functions read settings through contexts set in `applySettings` (`context.ts`, `sounds.ts`). Rest sounds are tone lists in `src/lib/sounds.ts`, shared by the in-app beep and the lock-screen track. "Previous" values go through `previousSession` (`src/lib/previous.ts`); the backup reminder's rule is `backupDue` (`src/lib/backupReminder.ts`).
- **Languages** (`src/i18n/`): the typed English catalog in `en/*.ts` is the source of truth (`Message = string | { one, other, … }`, `{placeholders}`, `<b>` `<link>` `<em>` for `tRich`). The ten other languages are machine translations in `<code>/{base,screens,settings}.ts`, merged by `<code>.ts` into a `Catalog`, so the type check fails on a missing key; `LOADERS` in `index.ts` lazy-loads each one (the service worker precaches the chunks). `i18n.test.ts` checks every language for the same keys, the same placeholders and tags, and the plural forms `Intl.PluralRules` needs for 0 to 1000 (Indonesian has only `other`, so it uses plain strings). A new string goes into the English file and then into all ten. Numbers with a Latin unit ("66 kg × 15", "−15") go through `isolate()` (`src/lib/format.ts`) so Arabic keeps them in reading order; `plain()` strips the marks for canvas text and anything parsed back. Arabic (`dir="rtl"`): logical CSS, `.flip-rtl` on directional icons, charts and the calendar kept left to right, Western digits, `letter-spacing: 0` for `html[lang='ar']`, and Noto Sans Arabic loaded only for Arabic text (not precached; the `arabic-font` runtime cache). Exercise names and instructions are English library data in every language.
- **Public launch pieces:** link-preview tags live in `index.html` with `__SITE_URL__` filled by `vite.config.ts` (`SITE_URL`, default the live site); `public/og-image.jpg` and `public/store/*` are served but not precached. Manifest `shortcuts` open `#/?action=start` / `#/?action=weigh`, handled by `useLaunchAction` (`src/lib/launch.ts`). `public/privacy.html` is a static page the service worker must not answer with the app shell (`navigateFallbackDenylist`). `WidePanel` fills the side of the phone-width column from 1240 px. "What's new": add a version to `WHATS_NEW` (`src/lib/whatsNew.ts`) with catalog keys in all eleven languages and bump `package.json`; `lastSeenVersion` (a pref) decides who sees the sheet. Store notes: `.ai/PLAY_STORE.md`, assets in `branding/store/`.
- **First run, programs, past workouts:** `#/welcome` is shown only when `shouldWelcome` (`src/lib/welcome.ts`) says the install is empty and `welcomeSeen` (a pref) is unset; Home does the redirect. Starter programs are data in `src/data/programs.ts` (library exercise ids, catalog keys for titles); `addProgram` saves them as routines in a folder named after the program. `#/history/new` is `EditWorkout`'s editor with a blank workout and the draft key `workout:new`. Progress's recent records come from `recentRecords` (`src/lib/records.ts`) over `computeRecords`; `recordFormat` formats a record's value. Welcome, Programs and Settings are lazy chunks.
- **`useSettings()`** caches the last read, so sheets and forms that mount later start with the real settings instead of the defaults. Initial `useState` values computed from settings rely on this.
- **Exercise demo** (`ExerciseDemo`, top of the exercise page): free-exercise-db has a start and an end photo for most exercises (873 of 1,003), which a CSS keyframe flips between like a short clip. Commercial apps' 3D exercise animations are licensed libraries, so don't copy them. Real animations would mean a paid licence, which conflicts with keeping Chalk free.
- **Share card:** `src/lib/shareCard.ts` draws the workout summary PNG (1080×1350) on a canvas. It follows the Forward look (glow, slanted records banner); its colours are the `C` constants and the slant is `SLANT`, so change them if the tokens change.
- **Import and export:** `importer.ts` is format-neutral (`ParsedWorkout` → `planImport` → `applyImport`, duplicates matched by start second and title). `strong.ts` reads Strong's CSV (units from a column, the header or the user's choice; W/D/F set orders; rest-timer rows skipped). `exportCsv.ts` writes and reads Setward's own CSV (units in the column names, local dates). `readWorkoutCsv()` tells them apart by header.
- **Records:** `computeRecords()` walks workouts oldest to newest. The first session of an exercise sets the baseline and doesn't count as a record.
- **Crash recovery:** `ErrorBoundary` wraps the app in `main.tsx`. Its `RecoveryScreen`, also shown when boot fails, offers Reload and a backup download that reads IndexedDB directly, so it works however broken the React state is. Unhandled promise rejections show a toast.
- **Backup restore** is check, then confirm, then write: `parseBackup()` (pure) → confirm sheet with counts → `restoreBackup()`. `src/lib/validate.ts` drops damaged records and counts them, and repairs only what Chalk can derive (`exerciseIds`, unknown labels, JSON `null` numbers). Don't validate sync input the same way: a filtered record would look deleted locally and the deletion would sync to the cloud.
- **Data check** (Settings → Your data, and the crash screen): `src/lib/dataCheck.ts` runs the restore cleaners over what is stored, with no React or `DataProvider` so the crash screen can use it. A cleaner returning `null` means damaged (delete only); a cleaned copy that differs from the record means repairable (it is rewritten, unknown fields kept). Comparison is canonical JSON with `exerciseIds` as a set. Repair and delete re-read the record inside a transaction and skip it if it changed. Nothing changes without a tap, because filtering automatically would look like a deletion to sync.
- **Editor drafts:** the routine and past-workout editors write their state to `kv` under `draft:<kind>:<id>` (`useDraft` in `src/lib/drafts.ts`), so the back gesture or a link doesn't lose edits. The Back button asks before discarding. See `.ai/decisions/ADR-001-editor-drafts.md`.
- **Stopwatch for timed sets** (live mode, exercises with a duration field): `ActiveWorkout.stopwatch` holds `{ setId, startedAt }`, so it survives a reload, and `workoutFromDraft` never copies it into the saved workout. `StopwatchPanel` in `WorkoutEditor` times the next set that isn't done, rings once (Web Audio beep and vibration from `timer.ts`) at the target: the set's own time, else last session's, else the set before. Stop, or the set's check button, saves the time, checks the set and starts the rest; starting it ends a running rest.
- **Routine order:** each routine has an `order`; folders are sorted A–Z. `ReorderSheet` (`src/components/RoutineFolders.tsx`, from a routine's or folder's ⋯ menu) reorders one folder by drag handle, arrow buttons or arrow keys. `reorderedRoutines` (`src/lib/folders.ts`) reuses the group's own order values, so other folders keep their places.
- **Content Security Policy:** production builds get a CSP meta tag from `vite.config.ts` (not the dev server). A new network origin, such as Google sync, must be added to its `connect-src`.

## Design
- **Forward look (1.0):** the glow and gradient (`.btn-glow`, `--hero-grad`, `--glow`) belong to hero elements only (Start workout, Finish, the week card, the celebration); big numbers use Big Shoulders; the split-S slant (`--slant-clip`, `--slant-end`, `SlantBar`, `.slant-chip`, the active tab pill) marks progress, goal and streak; cards are layered (`--surface-hi`, `--lift`, `--elev-*`); no all-caps eyebrow labels. Run `node scripts/contrast.mjs` after any token change: it checks every theme, black, high-contrast and accent combination (text 4.5:1, indicators 3:1). F and D badge text uses `--fail-ink` / `--drop-ink`, not the ring colours.
- **Tokens** are in `src/styles.css` (dark default, light via `[data-theme]`). The palette is violet-tinted charcoal greys with a purple accent: `--accent` #7a55e6 dark / #5b3cc4 light for fills (white text) and indicators, and `--accent-ink` for purple text. The app icons in `public/` are drawn in the same colours.
- **Fonts:** Big Shoulders Display for titles, clocks and badges; Archivo for everything else. Both are self-hosted through Fontsource so they work offline.
- **Set badges:** W orange (`--warmup`), F red and D blue (bumper-plate colours). A done row is green. Toggles use the accent. The yellow `--warm` is now only the 15 kg plate in the plate calculator.
- **Chart colour** is `--viz`: #8b6cf0 dark / #6a4bd6 light, checked with the dataviz palette validator against `--surface`.
- **Grey text** `--text-3` (#888692 dark / #656371 light) is the dimmest text allowed: 4.5:1 or more on `--bg` and `--surface`.
- **Narrow phones:** check new screens at 360 px. Grid and flex children that hold wide content (charts, scrollers, tables) need `min-width: 0`, or they push the page sideways. When sweeping for overflow in the dev browser, compare against `document.documentElement.clientWidth`, not `window.innerWidth`: a phone-sized browser widens `innerWidth` to fit an overflowing page, so a check against it passes.
